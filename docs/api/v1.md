# Silver App API v1 명세

이 문서가 앱과 백엔드 사이 API의 기준입니다. API를 바꾸는 PR은 이 문서도 함께 수정하고 `api-change` 라벨을 붙입니다.

## 공통

- Base URL: `https://<vercel-domain>/api/v1`
- 인증: 모든 `/api/v1/*` 요청에 `X-Device-Token: <token>` 헤더
- 요청/응답: `application/json` (UTF-8)
- 에러 형식:
  ```json
  { "error": { "code": "unauthorized", "message": "유효하지 않은 기기 토큰입니다." } }
  ```
- 하위 호환 원칙: 필드 추가는 허용, 필드 삭제나 의미 변경은 `/api/v2`로 올립니다.

| 상태 | 엔드포인트 | 단계 |
|---|---|---|
| ✅ 구현 | `GET /api/health` | 0 |
| ✅ 구현 | `POST /api/v1/kiosk/guide` | 1 |
| ✅ 구현 | `POST /api/v1/messages/classify` | 3 |
| 📝 설계 | `POST /api/v1/numbers/check` | 4 |
| 📝 설계 | `POST /api/v1/calls/consult` | 4 |

## `GET /api/health`

인증 없음.

```json
{ "status": "ok", "version": "a1b2c3d", "time": "2026-10-28T09:00:00.000Z" }
```

## `POST /api/v1/kiosk/guide`

키오스크 화면 사진과 사용자의 목표를 받아 **다음 한 단계**를 안내합니다.

요청:
```json
{
  "sessionId": "uuid (첫 요청에는 생략, 응답으로 받은 값을 이후 재사용)",
  "goal": "불고기버거 먹고 싶어",
  "image": "base64 JPEG (긴 변 1024px 이하, 1MB 이하 권장)",
  "mediaType": "image/jpeg",
  "history": [
    { "speech": "화면 왼쪽의 '버거' 버튼을 누르세요." }
  ],
  "userReply": "단품으로 할래"
}
```
- `mediaType`: `image/jpeg`(기본) | `image/png` | `image/webp`
- `history`: 앱이 이 세션에서 읽어준 안내들, 오래된 것부터. 최대 30개. 서버는 세션을 저장하지 않으므로 앱이 들고 다닙니다.
- `userReply`: 직전 응답이 `need_input`이었을 때 사용자의 대답. 그 외에는 생략.

응답:
```json
{
  "sessionId": "uuid",
  "speech": "'불고기버거' 사진을 누르세요. 위에서 두 번째 줄 첫 번째에 있어요.",
  "target": { "label": "불고기버거", "box": [0.12, 0.30, 0.35, 0.48] },
  "status": "in_progress"
}
```
- `target.box`: `[x1, y1, x2, y2]`, 이미지 크기 대비 0~1 비율. 없을 수 있습니다.
- `status`:
  - `in_progress`: 진행 중
  - `done`: 주문 완료
  - `need_input`: 사용자 답이 필요함 (예: "세트로 하실래요?")
  - `unclear`: 화면이 잘 안 보임, 다시 찍기 요청

에러:
| 상태 | `code` | 의미 |
|---|---|---|
| 400 | `invalid_json`, `invalid_request` | 요청 형식 오류 |
| 401 | `unauthorized` | 기기 토큰 없음/틀림 |
| 413 | `image_too_large` | 이미지 base64가 3,000,000자 초과 |
| 422 | `refused` | 안내할 수 없는 화면 (안전 정책) |
| 429 | `rate_limited` | 잠시 후 재시도 |
| 500 / 502 | `internal_error`, `upstream_error`, `bad_model_output` | 서버 또는 LLM 오류, 재시도 |

응답까지 보통 수 초가 걸립니다. 앱은 타임아웃을 60초로 잡습니다.

## `POST /api/v1/messages/classify`

기기 안 1차 규칙에서 "의심"으로 분류된 메시지만 보냅니다. 계좌번호, 주민번호 등은 앱에서 가린 뒤 보냅니다.

요청:
```json
{
  "source": "sms | kakao | other",
  "sender": "01012345678 또는 표시 이름",
  "senderInContacts": false,
  "body": "[Web발신] 고객님 택배가 주소 불일치로 보류되었습니다 http://bit.ly/xxxx",
  "ruleHits": ["short_url", "keyword:택배"]
}
```

응답:
```json
{
  "verdict": "safe | suspicious | malicious",
  "category": "delivery_scam | gov_impersonation | family_impersonation | payment_scam | invitation_scam | loan | investment | other | none",
  "reason": "택배 회사인 척하는 사기 문자예요. 안에 있는 주소를 누르지 마세요."
}
```
- 앱 처리:
  - `malicious`: 알림 제거 후 격리함으로
  - `suspicious`: 경고 표시
  - `safe`: 그대로 둠
- `reason`: 어르신께 보여주고 읽어드릴 쉬운 설명 (해요체, 두 문장 이내)
- 제한: `body` 최대 2000자, `ruleHits` 최대 20개

에러: 400 `invalid_json`/`invalid_request`, 401 `unauthorized`, 422 `refused`, 429 `rate_limited`, 500/502.

**판정에 실패하면(에러, 타임아웃, 오프라인) 앱은 자기 규칙 결과로 처리합니다.** 규칙의 위험 신호가 강하면 경고하되, 서버 판정 없이 메시지를 숨기지는 않습니다.

## `POST /api/v1/numbers/check`

전화가 오는 순간 번호 평판을 조회합니다. LLM을 쓰지 않고 빠르게 응답합니다(목표 300ms 이내).

요청:
```json
{ "number": "+82701234567", "inContacts": false }
```

응답:
```json
{
  "risk": "low | medium | high",
  "reasons": ["international", "reported"],
  "action": "allow | warn | block"
}
```

---

## `POST /api/v1/calls/consult`

의심 번호와 통화한 뒤 사용자가 들은 내용을 말하면, 보이스피싱인지 판단해 쉽게 설명합니다.

요청:
```json
{
  "number": "+82701234567",
  "durationSec": 320,
  "transcript": "검찰이라면서 내 계좌가 범죄에 쓰였대. 돈을 안전계좌로 옮기래.",
  "followUpSignals": ["remote_app_installed"]
}
```

응답:
```json
{
  "verdict": "safe | suspicious | malicious",
  "speech": "검찰은 전화로 돈을 옮기라고 하지 않아요. 보이스피싱이에요. 돈을 보내지 마시고 112에 신고하세요.",
  "recommendedActions": ["call_112", "notify_guardian", "uninstall_remote_app"]
}
```
