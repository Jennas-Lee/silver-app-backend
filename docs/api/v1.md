# Silver App API v1 명세

이 문서가 앱과 백엔드 사이 API의 기준입니다. API를 바꾸는 PR은 이 문서도 함께 수정하고 `api-change` 라벨을 붙입니다.

## 공통

- Base URL: `https://<vercel-domain>/api/v1`
- 인증: 로그인 토큰을 `Authorization: Bearer <token>` 헤더로 보냅니다 (아래 "계정").
  - 개발·평가 스크립트용: 문자 판정·주소 판정·키오스크 안내는 로그인 토큰이 없을 때 `X-Device-Token`도 받습니다. 앱은 쓰지 않습니다.
- **어르신은 보호자와 연결되어야 기능을 쓸 수 있습니다.** 연결된 보호자가 없으면 아래 API는 403 `guardian_required`를 돌려줍니다.
  - 문자 판정, 주소 판정, 키오스크 안내, 기록 올리기(`POST /records`, `POST /url-records`)
  - 연결 전에도 되는 것: 계정 만들기·로그아웃, `GET /me`, 연결 코드 받기, 연결 목록, 연결 끊기, 기록 지우기
- 요청/응답: `application/json` (UTF-8)
- 에러 형식:
  ```json
  { "error": { "code": "unauthorized", "message": "유효하지 않은 기기 토큰입니다." } }
  ```
- 하위 호환 원칙: 필드 추가는 허용, 필드 삭제나 의미 변경은 `/api/v2`로 올립니다.

| 상태 | 엔드포인트 | 단계 |
|---|---|---|
| ✅ 구현 | `GET /api/health` | 0 |
| ✅ 구현 | `POST /api/v1/kiosk/guide` | 1 |
| ✅ 구현 | `POST /api/v1/messages/classify` | 3 |
| ✅ 구현 | 계정: `POST /api/v1/auth/senior`, `POST /api/v1/auth/guardian/signup`, `POST /api/v1/auth/guardian/login`, `POST /api/v1/auth/logout`, `GET /api/v1/me` | 5 |
| ✅ 구현 | 연결: `POST /api/v1/links/code`, `POST /api/v1/links`, `GET /api/v1/links`, `DELETE /api/v1/links/{userId}` | 5 |
| ✅ 구현 | 기록: `POST /api/v1/records`, `DELETE /api/v1/records/{id}`, `GET /api/v1/seniors/{id}/records` | 5 |
| ✅ 구현 | `POST /api/v1/urls/check` | 6 |
| ✅ 구현 | 막은 주소: `POST /api/v1/url-records`, `DELETE /api/v1/url-records/{id}`, `GET /api/v1/seniors/{id}/url-records` | 6 |
| 📝 설계 | `POST /api/v1/numbers/check` | 4 |
| 📝 설계 | `POST /api/v1/calls/consult` | 4 |

## `POST /api/v1/kiosk/guide`

키오스크 화면 사진과 사용자의 목표를 받아 **다음 한 단계**를 안내합니다.

요청:
```json
{
  "sessionId": "uuid (첫 요청에는 생략, 응답으로 받은 값을 이후 재사용)",
  "goal": "불고기버거 먹고 싶어",
  "image": "base64 JPEG (긴 변 1024px 이하, 1MB 이하 권장)",
  "mediaType": "image/jpeg",
  "history": [
    { "speech": "화면 왼쪽의 '버거' 버튼을 누르세요." }
  ],
  "userReply": "단품으로 할래"
}
```
- `mediaType`: `image/jpeg`(기본) | `image/png` | `image/webp`
- `history`: 앱이 이 세션에서 읽어준 안내들, 오래된 것부터. 최대 30개. 서버는 세션을 저장하지 않으므로 앱이 들고 다닙니다.
- `userReply`: 직전 응답이 `need_input`이었을 때 사용자의 대답. 그 외에는 생략.

응답:
```json
{
  "sessionId": "uuid",
  "speech": "'불고기버거' 사진을 누르세요. 위에서 두 번째 줄 첫 번째에 있어요.",
  "target": { "label": "불고기버거", "box": [0.12, 0.30, 0.35, 0.48] },
  "status": "in_progress"
}
```
- `target.box`: `[x1, y1, x2, y2]`, 이미지 크기 대비 0~1 비율. 없을 수 있습니다.
- `status`:
  - `in_progress`: 진행 중
  - `done`: 주문 완료
  - `need_input`: 사용자 답이 필요함 (예: "세트로 하실래요?")
  - `unclear`: 화면이 잘 안 보임, 다시 찍기 요청

에러:
| 상태 | `code` | 의미 |
|---|---|---|
| 400 | `invalid_json`, `invalid_request` | 요청 형식 오류 |
| 401 | `unauthorized` | 기기 토큰 없음/틀림 |
| 413 | `image_too_large` | 이미지 base64가 3,000,000자 초과 |
| 422 | `refused` | 안내할 수 없는 화면 (안전 정책) |
| 429 | `rate_limited` | 잠시 후 재시도 |
| 500 / 502 | `internal_error`, `upstream_error`, `bad_model_output` | 서버 또는 LLM 오류, 재시도 |

응답까지 보통 수 초가 걸립니다. 앱은 타임아웃을 60초로 잡습니다.

## `POST /api/v1/messages/classify`

기기 안 1차 규칙에서 "의심"으로 분류된 메시지만 보냅니다. 계좌번호, 주민번호 등은 앱에서 가린 뒤 보냅니다.

요청:
```json
{
  "source": "sms | kakao | other",
  "sender": "01012345678 또는 표시 이름",
  "senderInContacts": false,
  "body": "[Web발신] 고객님 택배가 주소 불일치로 보류되었습니다 http://bit.ly/xxxx",
  "ruleHits": ["short_url", "keyword:택배"]
}
```

응답:
```json
{
  "verdict": "safe | suspicious | malicious",
  "category": "delivery_scam | gov_impersonation | family_impersonation | payment_scam | invitation_scam | loan | investment | other | none",
  "reason": "택배 회사인 척하는 사기 문자예요. 안에 있는 주소를 누르지 마세요."
}
```
- 앱 처리:
  - `malicious`: 알림 제거 후 격리함으로
  - `suspicious`: 경고 표시
  - `safe`: 그대로 둠
- `reason`: 어르신께 보여주고 읽어드릴 쉬운 설명 (해요체, 두 문장 이내)
- 제한: `body` 최대 2000자, `ruleHits` 최대 20개

에러: 400 `invalid_json`/`invalid_request`, 401 `unauthorized`, 422 `refused`, 429 `rate_limited`, 500/502.

**판정에 실패하면(에러, 타임아웃, 오프라인) 앱은 자기 규칙 결과로 처리합니다.** 규칙의 위험 신호가 강하면 경고하되, 서버 판정 없이 메시지를 숨기지는 않습니다.

## `POST /api/v1/urls/check`

어르신이 열려는 인터넷 주소(문자·카톡 속 주소, QR 코드, 인터넷 창 주소)가 위험한지 판정합니다. 한 번에 최대 10개, 요청한 순서대로 응답합니다.

요청:
```json
{ "urls": ["http://kbstar-login.top/auth", "m.naver.com"] }
```
- `http(s)://`가 없어도 됩니다. `tel:` 같은 인터넷 주소가 아닌 것은 `unknown`으로 돌려줍니다.
- 앱은 주소의 `?` 뒤(검색어, 로그인 정보 등)를 지우고 보내는 것을 권장합니다. 서버도 판정할 때 `?` 뒤를 쓰지 않습니다.

응답:
```json
{
  "results": [
    {
      "url": "http://kbstar-login.top/auth",
      "host": "kbstar-login.top",
      "verdict": "safe | suspicious | malicious | unknown",
      "category": "phishing | malware | scam | other | none",
      "reason": "국민은행인 척하는 가짜 주소예요. 아이디와 비밀번호를 절대 넣지 마세요.",
      "source": "rule | webrisk | model | invalid | error",
      "cached": false
    }
  ]
}
```
- 앱 처리:
  - `malicious`: 바로 뒤로 가기 + 경고, 보호자 기록(`BLOCKED`)
  - `suspicious`: 경고만, 보호자 기록(`WARNED`)
  - `safe`, `unknown`: 그대로 둠 (`unknown`은 판정 실패. 막지 않습니다)
- 판정 순서: 공식 도메인·`.apk` 규칙 → 저장된 판정 → Google Web Risk(`WEB_RISK_API_KEY`가 있을 때) → Claude
- 판정은 도메인 단위로 저장해 다시 씁니다(위험 30일, 그 외 3일). 구글 문서·블로그·짧은 주소처럼 여러 사람이 같이 쓰는 도메인은 도메인 + 경로 단위입니다.
- `category`가 `none`이 아니어도 `verdict`가 `safe`일 수 있습니다. 처리는 `verdict`로 정합니다.

에러: 400 `invalid_request`, 401 `unauthorized`. 주소 하나가 판정에 실패해도 전체 요청은 200이고, 그 주소만 `unknown`입니다.

## 계정

계정은 두 종류입니다. 어르신은 이름만으로 만들고(휴대폰 한 대 = 계정 하나), 보호자는 이메일·비밀번호로 만듭니다.
응답의 `token`을 앱에 저장해 이후 모든 요청에 `Authorization: Bearer <token>`으로 보냅니다. 서버에는 토큰의 해시만 저장됩니다.

| 요청 | 본문 | 응답 |
|---|---|---|
| `POST /api/v1/auth/senior` | `{ "name": "김순자" }` | 201 `{ token, user }` |
| `POST /api/v1/auth/guardian/signup` | `{ "name", "email", "password" }` (비밀번호 8자 이상) | 201 `{ token, user }`, 409 `email_taken` |
| `POST /api/v1/auth/guardian/login` | `{ "email", "password" }` | 200 `{ token, user }`, 401 `invalid_credentials` |
| `POST /api/v1/auth/logout` | (토큰) | 204 |
| `GET /api/v1/me` | (토큰) | 200 `{ user }`, 401. 어르신이면 `user.hasGuardian`(보호자 연결 여부)도 줍니다 |

`user`: `{ "id": "uuid", "role": "senior | guardian", "name": "김순자", "email": null }`

## 연결 (보호자 ↔ 어르신)

1. 어르신 앱이 `POST /api/v1/links/code`로 6자리 코드를 받아 크게 보여줍니다 (10분 유효, 새로 받으면 예전 코드는 사라짐).
2. 보호자 앱에서 코드를 입력하면 `POST /api/v1/links` `{ "code": "123456" }` → 201 `{ senior }`. 코드는 한 번 쓰면 사라집니다. 틀리거나 시간이 지나면 404 `invalid_code`.

`GET /api/v1/links`
- 보호자: `{ "seniors": [{ ...user, "linkedAt", "recentCount": 3, "recentUrlCount": 1, "lastRecordAt": "ISO | null" }] }`
  - `recentCount`: 최근 7일 차단·경고 문자 수, `recentUrlCount`: 최근 7일 막거나 경고한 주소 수
  - `lastRecordAt`: 문자·주소 기록 중 가장 최근 시각
- 어르신: `{ "guardians": [{ ...user, "linkedAt" }] }`

`DELETE /api/v1/links/{userId}`: 보호자는 어르신을, 어르신은 보호자를 연결에서 뺍니다. 204.

한 어르신에 보호자 여러 명, 한 보호자에 어르신 여러 명을 연결할 수 있습니다.

## 차단 기록

`POST /api/v1/records` (어르신): 휴대폰의 차단·경고 기록을 올립니다. 최대 100건씩.
```json
{ "records": [{ "id": "앱의 기록 ID", "receivedAt": "ISO", "source": "sms", "sender": "+447700900123",
  "body": "개인정보를 가린 본문", "action": "HIDDEN | WARNED", "category": "delivery_scam", "reason": "쉬운 설명" }] }
```
→ `{ "received": 2, "saved": 2 }`. 같은 `id`는 한 번만 저장됩니다. 본문은 서버에서도 개인정보(주민·카드·계좌번호)를 한 번 더 가립니다.

`DELETE /api/v1/records/{id}` (어르신): 어르신이 목록에서 지운 기록을 서버에서도 지웁니다. 204.

`GET /api/v1/seniors/{id}/records?limit=50&before=ISO` (보호자): 연결된 어르신의 기록, 최신순. `before`로 이전 기록을 이어서 불러옵니다. 연결되지 않았으면 404 `not_linked`.

## 막은 주소 기록

`POST /api/v1/url-records` (어르신): 휴대폰에서 막거나 경고한 인터넷 주소를 올립니다. 최대 100건씩.
```json
{ "records": [{ "id": "앱의 기록 ID", "visitedAt": "ISO", "url": "http://kbstar-login.top/auth",
  "app": "크롬", "action": "BLOCKED | WARNED", "category": "phishing", "reason": "쉬운 설명" }] }
```
→ `{ "received": 1, "saved": 1 }`. 같은 `id`는 한 번만 저장됩니다.
- `app`: 주소를 연 곳을 사람이 읽는 이름으로 (예: `크롬`, `삼성 인터넷`, `네이버`, `카카오톡`, `문자`, `QR`).
- 서버는 주소의 `?`·`#` 뒤를 버리고, 경로의 개인정보(주민·카드·계좌번호)를 가려서 저장합니다. 방문한 모든 주소가 아니라 막거나 경고한 주소만 올립니다.

`DELETE /api/v1/url-records/{id}` (어르신): 204.

`GET /api/v1/seniors/{id}/url-records?limit=50&before=ISO` (보호자): 연결된 어르신의 막은 주소, 최신순. 연결되지 않았으면 404 `not_linked`.
```json
{ "records": [{ "id": "...", "visitedAt": "ISO", "host": "kbstar-login.top", "url": "kbstar-login.top/auth",
  "app": "크롬", "action": "BLOCKED", "category": "phishing", "reason": "..." }] }
```
